## 1. 研究问题和三臂设计

**核心原则（用户）**：在无监督训练范式里，用能量模型修改参考过程，给采样器提供先验，从而提高训练效率。不限定在 ASBS 上。

**评估**：用 MIS 领域的优化指标（平均 MIS 大小、best-of-K、与 KaMIS 的差距），不再以分布距离为主。

**三臂**：每一臂内部比较"基线 vs + 能量"。

| 臂 | 状态空间 | 基线 | + 能量 | 代码 |
|---|---|---|---|---|
| AS | 连续，单点源，解析 corrector | AS，f=0 | AS + B1+ 能量漂移参考过程 | `sbmis/` |
| ASBS | 连续，高斯源，学 corrector | B0，f=0 | B1+（另有各向同性 OU、B0+prior 两个对照） | `sbmis/` |
| CAM | 离散 {0,1}^N | CAM（官方实现） | **CAMPrior** = CAM + RLSA 能量翻转先验 + 网络残差 | `cam/`（CAM 公开代码副本） |

**新颖性**（`related_work_eval.md` §7–§8）：
- 用连续时间 AS/ASBS 做 MIS，没有找到先例。
- 但"连续空间无监督 MIS"已经有 BloGDiT、PQQA 等工作；"用能量构造噪声或参考过程"也已有 DiffUCO 的能量退火噪声。
- 主贡献应落在：与生成同向的能量参考过程 / 先验，加上训练效率证据。

## 2. CAM 臂（目前最有进展）

### 2.1 做了什么

- **代码**：CAM 公开代码（Shengyu-Feng/CAM@b8c6167，作者是用户的学长，经同意使用）复制在 `cam/`。所有本地修改列在 `cam/UPSTREAM.md`：
  - 不再交互式确认，改成直接报错；
  - 测试时输出每张图的结果；
  - 每个 epoch 存 checkpoint，并在训练前先存一份初始权重 `epoch_init.pt`；
  - GPU 检查：卡上有别人的进程就拒绝；
  - 单卡运行脚本和几条评测队列。
- **CAMPrior**（`cam/solvers/cam_prior.py`）：
  - 每个节点的翻转概率 = sigmoid(RLSA 先验 logit + 网络残差)。
  - 输出头零初始化，所以未训练时等于 RLSA。
  - 损失里把 CAM 的熵项换成对先验翻转过程的 KL。
  - 先验温度：外层跟着 CAM 的训练温度走，内层按 RLSA 的方式沿采样步降温。
  - 测试：`cam/tests/test_cam_prior.py`，5 个，残差为 0 时和 RLSA 逐步完全一致。
- **网络**：CAM 的 `EncodeProcessDecode`。8 层线性消息传递，隐藏维 64，约 18.3 万参数，不接收时间。参数和图的大小无关，所以能直接迁移到大图。
- **数据**：CAM 官方数据，本机 `/data/shengyuf/MIS/data_er`（只读），和 huggingface `shengyuf/CAM_data` 逐个核对过校验值。
  - 训练集：DIFUSCO 生成的编号 100–16383，共 16284 张。
  - validation：编号 0–99，CAM 训练时只用前 64 张，按它挑 `best.pt`。
  - test：DIMES 发布的 128 张，CAM 论文用的就是这批。
  - ER-[9000-11000]：16 张，只用来测迁移，不训练。
- **数据分布检查**（`runs/scratch/data_check/`）：validation、test 和训练集的节点数、密度、度数、KaMIS 解大小都没有显著差异；编号和这些量之间也没有趋势。

### 2.4 读法（都只有 1 个种子）

- **训练效率**：CAMPrior 起点就在 RLSA 附近（约 40），训练 1 个 epoch 后到 42.3–43.5。CAM 从随机网络起步（约 32.5），前期剧烈波动，τ0=0.05 那组前 50 个 epoch 一直在 34–37。
- 作为参照，学长本地 wandb 里的开发版 CAM（τ0=0.5，和公开配置不同）要 60–240 个 epoch 才到 40。
- **最好的 CAMPrior τ0=1.0**：test 上第 10 个 epoch 起稳定在 43.8–44.2，第 80 个 epoch 是 44.20，与 CAM 论文训练 1000 个 epoch 的 44.16 持平。
- **泛化**：CAMPrior τ0=0.1 和 1.0 在大图上稳定在 380–384，多次超过 KaMIS。CAM 后期才追上来。
- **异常**：CAMPrior τ0=0.01（先验最硬）在小图上稳定在约 43，但大图泛化从第 20 个 epoch 起掉到约 300，比 RLSA 还低 40 个节点。原因未查。
- **先验饱和**：τ0=0.01 时 87% 的坐标翻转概率饱和成 0 或 1，残差几乎学不动，所以这组基本停在 RLSA 水平附近。
- **最后几个 epoch 下滑**：训练温度退火到接近 0 时，CAMPrior 的 test 从约 44.1 掉到 43.1–43.8；CAMPrior τ0=0.1 的大图泛化在第 100 个 epoch 掉到 306.7，第 90 个 epoch 还是 381.8。所以最终数字用 `best.pt`。原因可能和外层温度绑定有关：训练温度趋于 0 时先验 logit 被放大（最多 100 倍，见 `--prior_tau_min`），先验变硬，和 τ0=0.01 的饱和类似。消融里"先验温度不绑定"那一组可以直接检验这一点。
- **按 `best.pt`**：CAMPrior τ0=1.0 在 test 上 44.18 对 CAM 44.04，大图上 383.3 对 379.3，和 CAM 论文训练 1000 epoch 的 44.16、384.38 持平。只有 1 个种子，差距在种子波动范围内，要等补种子的结果。

### 2.6 RB-small 和 RB-large（原集群，种子 0，11-11 全部完成）

**为什么做**：把 ER 上的结论横向推广到 CAM 论文里另外两个 MIS 数据集。CAM 论文在 MIS 上训了 3 个独立模型：ER-[700-800]、RB-[200-300]（small）和 RB-[800-1200]（large）。ER-[9000-11000] 只做迁移测试，不单独训练（论文 §5.1，官方脚本 `mis_rb_{small,large}_cam.sh`，huggingface 上的 3 个 checkpoint）。

**设定**：沿用 ER 的协议，即单卡、官方 epoch 数的十分之一（温度退火和学习率衰减都按缩短后的长度走完）、种子 0，其余超参数照官方脚本，由 `cam/scripts/mis/mis_rb_cam.sh` 统一设置。

| | RB-small | RB-large |
|---|---|---|
| 训练 epoch | 100 | 150 |
| 每个 epoch 的图数 / 每次迭代的图数 | 4000 / 4 | 1000 / 1 |
| mini-batch / 训练时每张图的链数 / 网络层数 | 256 / 10 / 8 | 128 / 20 / 6 |
| CAM 组 | τ0=0.1 | τ0=0.1 |
| CAMPrior 组 | 先验 τ0=1.0，d=5 | 先验 τ0=1.0，**d=20** |
| 每个 epoch 耗时（2080 Ti） | 约 20 分钟 | 约 29 分钟 |
| 预计结束 | 11-10 周二早上约 5 点 | 11-11 周三晚上约 9 点 |

**先验步长 d 怎么选（11-08 和用户商定）**：每个数据集都在 64 张 validation 图上、按 CAM 的采样预算（50 步 × 20 条链）来选，不看 test。
- RLSA 原论文（RLD 附录 Table 4）在 RB 上用 d=5，但那是配 300–500 步、200 条链调的。
- 在 RB-large 上，50 步里每步只翻约 5 个点，清不掉随机起点里约 500 个冲突的点。所以 d=5 时，CAMPrior 未训练的水平（即 τ0=1.0 的 RLSA）只有 33.61，和随机网络差不多；d=20 是 34.41。在同一批图上配对比较，d=20 比 d=5 高 0.80 ± 0.13。d=20 到 d=100 之间的差别都在噪声内。
- RB-small 上 d=5 最好，d=20 反而低 0.41 ± 0.10。
- 扫描结果在 `runs/scratch/verify_rb/rlsa_{small,large}/`。

**同预算 RLSA 基线**：按同样的规则在 validation 上调到最好，同时报 RLD 原设定作参考，结果在 `runs/cam/mis_rb_rlsa/`。

**启动前的独立核查（11-08）**：原始报告在 `runs/scratch/verify_rb/reports.md`。
- **超参数**：传给训练程序的每一项都和官方 RB 脚本一致。
- **数据**：本机 11000 个 RB 文件和 huggingface 发布的 MIS.zip 逐个文件核对，文件名、大小、CRC32 全部一致。train、validation、test 之间没有重复的图。
- **CAMPrior 的拼批**：RB-small 每次迭代把 4 张图拼成一批。核查确认先验仍按每张图分别计算，在真实 RB 图上和 RLSA 逐位一致。
- **官方多卡训练的学习率问题**：上游代码在多卡时，余弦学习率实际推进得比设计快 8 倍（accelerate 包装后的调度器每个进程各走一步），8 卡训练里学习率来回 4 个周期，最后回到最大值。单卡的我们是正常衰减一次到 0。这不影响 CAM 和 CAMPrior 之间的对比，但和论文数字比较时要注意。ER 也一样。
- **最后一个 epoch 的温度更高**：epoch 缩短十倍后，最后一个 epoch 的训练温度是官方的 10 倍。ER 也一样。
- **RB-small 接近饱和**：CAM 论文 19.91，KaMIS 20.10，每张图的标准差约 1.5，最终分数大概率分不出高下，差别主要会体现在训练早期。RB-large 上 CAM 离 KaMIS 还差 4.4%，是主要看点。
- **KaMIS 参考值不是同一个 test 集**：论文里 RB 的 KaMIS 和 Gurobi 数字是从 DiffUCO 转引的，用的是 500 张图的另一个 test 集，所以和 KaMIS 的差距只能算近似。

**评测**：`cam/scripts/mis/rb_curve.sh`，每个规模 1000 张 test 图，50 步 × 20 条链；评测第 0、1、2、5、10、20、… 个 epoch，加上训练结束后的 best.pt，结果在 `runs/cam/mis_rb_{small,large}_test/`。评测卡先后被别的用户占用过几次（2、3、5 号卡），被放弃的点都在空出来的卡上补齐了，所有点都在 GPU 上评测。

**运行位置**：训练在 4–7 号卡（RB-small 11-10 凌晨训完，RB-large 11-11 15:30 训完）。日志在 `runs/queue_cam_rb/`，checkpoint 在 `runs/cam/mis_rb_{small,large}/<组>/`。

### 2.12 TSP：先验门槛检验（11-13，sa 集群，不训练）

**问题。** CAMPrior 在 MIS 上的先验是 RLSA：把标签用的算子（能量翻转梯度）作用在当前状态上。TSP 上 RLSA 不适用（RLSA 论文把 TSP 列为局限；度约束 QUBO 上单变量翻转凑不出 2-opt 那样的协调移动）。对应物改为 CAM 自己的终点启发式作用在当前状态上：每步把状态当热力图（与常数热力图混合，h = (1 − λ) + λ x，λ 从 0 线性升到 1）做贪心合并 + 2-opt，再以概率 0.5 把边往这个环翻，加退火的随机翻转。脚本 `cam/scripts/tsp/prior_gate.py`，数据 HF `TSP.zip`（`/home/shengyuf/yunyi/data/CAM_data/TSP/`），结果 `runs/tsp_gate/`。

**结果**（10 步 × 16 条链，结尾 1000 次 2-opt，与 CAM 测试协议一致；长度是 16 条链取最好的均值）

| 做法 | TSP-500 test（128） | TSP-1000 valid（32） |
|---|---|---|
| 随机状态 → 合并 → 2-opt（约等于未训练的 CAM） | 17.65 | 24.94 |
| 距离贪心 → 2-opt | 17.17 | 24.04 |
| 先验链，每步 2-opt 50 次 | **16.93** | **23.80** |
| 先验链，每步 2-opt 200 次 | 16.93 | — |
| 先验链，每步 2-opt 200 次（向量化 2-opt），16 条链 | 16.93 | — |
| 先验链，同上，24 条链（推理时间与 CAM 相当，见下） | **16.92** | — |
| 参照：CAM 论文（训练后，test） | 16.91 | 23.70 |
| 参照：SDDS / DIFUSCO（CAM 论文表 2） | 16.98 / 16.83 | 23.90 / 23.85 |

- 数据文件里参照环的平均长度是 16.58（TSP-500 test），CAM 论文表 2 的 Concorde / LKH-3 是 16.55，所以比较用绝对长度，不用 gap。
- 纯状态当热力图（λ 始终为 1）不行：链卡在 2-opt 局部最优，比距离贪心还差（验证集 4.3–6.2% vs 3.6%）。
- 每步不做 2-opt 时链本身不改进，只靠多样性（验证集最好 2.56%，每步做 2-opt 是 2.05%）。
- 不训练的先验链已经和训练后的 CAM 同一水平。
- **同样推理开销下的比较**（`cam/scripts/tsp/time_compare.py`，同一块共用 GPU、同 8 个实例，秒/实例）：CAM 推理（AnGNN 12 层 × 256、10 步 × 16 样本、合并、1000 次 2-opt；网络权重不影响耗时）16.4（训练后环已好，2-opt 早停）到 21.1（未训练的环）；其中网络前向 15.2。先验链：16 条链 10.0，24 条链 15.2（其中 CPU 上的贪心合并 12.0）。每步 2-opt 换成向量化实现（`fast_two_opt`，单环上与上游走法相同）后，先验从约 31 秒降到这个水平，质量不变。
